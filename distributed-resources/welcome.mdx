## Common to all DERs

Both integration types share the same MQTTS broker infrastructure and topic naming convention.

| Environment | Host | Port | Protocol |
|-------------|------|------|----------|
| Sandbox | `aggregator.gridhub.dev` | `8883` | MQTTS |
| Production | `n1.link.gridhub.ai` | `8883` | MQTTS |

All topics follow the pattern:

```
{priceZone}/{customerName}/v1/{channel}/{resourceId}
```

| Segment | Description |
|---------|-------------|
| `priceZone` | Grid bidding zone — `DK1` or `DK2` |
| `customerName` | Your assigned namespace |
| `v1` | API version segment |
| `channel` | Message type (`register`, `activation`, `power`, `measurement`, etc.) |
| `resourceId` | Unique identifier for the individual asset |

## Choosing between asset types

| | EV Chargers | Heat Pumps |
|---|-------------|-----------|
| Activation model | Power limit (kW value) | Directional (Up / Down / Release) |
| Telemetry | Raw power readings (kW) | Availability capacity (up/down kW) |
| Acknowledgement | Required | Not required |
| Bulk operations | Yes | No |
| Schedule sharing | No | Yes (zonal profiles) |
| Configuration | Capability level, current type | Compressor and backup heater rated power |

For assets that operate as both an EV charger and a storage device, see the [Delegated Operators](/delegated-operators/welcome) section — the BESS integration is handled through that layer.
